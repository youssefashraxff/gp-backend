# Web search comparison: Tavily, settings v1

Date: 2026-11-27 · Tool: Tavily · Settings: `tavily_v1` · Queries: `queries.json` v1
Status: **baseline**. The first run, used as the reference that later versions are compared against.

## Summary

Tavily's Egypt coverage is good: about **70% of results come from Egyptian sites**. The
`n_egyptian` column in `results.csv` shows much less, because the domain list missed most
Egyptian sites that don't end in `.eg`. The real weaknesses are the **kind of source** (mostly
developer and broker sales pages), **no dates** on any result, and two queries that return
mostly international pages.

## Weaknesses

1. **The Egyptian count was wrong.** `egypt_domains.txt` missed most Egyptian sites that don't end
   in `.eg`, such as Ouda, Valero, Aqarland, Subul, Invest-Gate and Egyptian Streets. The
   `n_egyptian` column underestimates coverage by a lot. This is a problem with the measurement,
   not with Tavily.
2. **Mostly sales pages.** Most Egyptian results are developers and brokers advertising their own
   projects. These are biased sources for market facts. Official and data sources are rare: SIS,
   MPED, Savills Egypt and the government real-estate blog appear only a few times.
3. **No dates.** In `general` topic, Tavily returns no `published_date` field. The evidence rule
   needs a date for each fact.
4. **Two queries miss the place.**
   - `sokhna_q1` returns global market-report pages about all of Egypt, mostly behind a paywall,
     and nothing about Sokhna.
   - `sokhna_q5` returns booking sites and event-venue directories instead of hotel numbers.
5. **A silent empty result.** `obour_q2` run 2 returned 0 results with no error. Without handling,
   an agent would treat this as "nothing exists".
6. **Odd result.** `sokhna_q1` returns a `tavily.com/knowledge/...` page every time. It's
   Tavily's own page, not a real source.

**Strength:** the results are very stable. The top 3 links are the same in 7–8 of the 8 runs for
almost every query.
