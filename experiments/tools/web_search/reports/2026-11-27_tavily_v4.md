# Web search comparison: Tavily, settings v4 (shorter restricted lists)

Date: 2026-11-27 · Tool: Tavily · Compared with: [v3](2026-11-27_tavily_arabic_and_v3.md)
Status: **tested, not adopted**. Shorter lists didn't reduce empty searches. The cause appears to
be a ~3-second time limit on Tavily's side.

## What changed from v3

One change: no `both` domains. Each citable site was assigned to Arabic or English only, so the
restricted lists shrank from about 60 and 90 domains to **30 (Arabic)** and **74 (English)**.
Same 3 searches, same queries, no retry. `score.py` was also fixed to normalise URLs before
counting unique results.

**Run:** 12 questions × 3 searches × 2 runs = 72 calls.

## Output

| | v3 | v4 |
|---|---|---|
| Arabic restricted: empty | 11 / 24 | **15 / 24** |
| English restricted: empty | 13 / 24 | 11 / 24 |
| All restricted searches empty | 24 / 48 | 26 / 48 |
| Results per restricted search, when not empty | 5.4 | 3.4 |
| Citable per question | 3.1 | 2.4 |
| News | 18% | 11% |
| Official | 4% | 8% |
| Developer / broker | 24% | 27% |
| Social | 5% | 8% |
| Time per question | 8.3 s | 7.7 s |

## Key finding: the empties are a time limit, not the list length

- Halving the Arabic list made the Arabic empties **worse** (11 → 15), so list length is not
  the cause.
- In the v4 run files, every empty restricted search has a Tavily `response_time` of
  **2.0–3.03 s, with a median of 3.01 s**. Successful ones have a median of 2.4 s.
- So when a restricted search can't finish in about 3 seconds, Tavily stops and returns an empty
  list with no error. This also explains why the same query is sometimes empty and sometimes not:
  it depends on how fast Tavily is at that moment.

This 3-second limit isn't in Tavily's documentation. It comes from our own run data.

## Other results

- **`unique_from_*` is now correct.** The open search adds about 9 unique results per question;
  the restricted searches add 1–2 each. Overlap between the searches is small.
- **Restricted searches return fewer results** with the shorter lists (3.4 against 5.4), which
  is why citable sources dropped against v3.

## Next

Restricted search in Tavily (`include_domains` + `restrict`) is unreliable for our use. Two
options:

1. **v5 (recommended): reverse the filter.** Two open searches (English + Arabic) with
   `exclude_domains` = developer/broker, social, paid-report and ignore domains from the CSVs.
   This removes the noise instead of naming the good sites, avoids the restricted path, and costs
   2 calls per question instead of 3.
2. **Test another tool for the restricted part** (Exa, Brave). That was already the next step of
   the tool comparison.

Keep v3 as the best result so far until v5 or another tool beats it.
